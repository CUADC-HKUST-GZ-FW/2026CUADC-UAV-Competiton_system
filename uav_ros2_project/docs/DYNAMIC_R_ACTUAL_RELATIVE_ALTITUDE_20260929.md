# 动态投弹接入实测相对高度说明（2026-09-29）

## 修改目的

此前动态 R 点虽然采集了实际相对高度、垂直速度和垂直加速度趋势，弹道计算却固定使用：

```text
h_R = mission_altitude_m
vz_R = 0
```

因此只有水平速度真正改变了投放距离。此次修改让动态模式使用 B 点冻结时的 MAVROS
相对高度，并根据 A-B 段垂直运动估计到达 R 点时的释放高度和垂直速度。

## 数据来源

- 高度：`/mavros/global_position/rel_alt`，在 B 点冻结为 `height_b_m`。
- 水平速度：A-B 时间窗内 `VFR_HUD.groundspeed` 在进攻航向上的投影加权均值。
- 垂直速度：A-B 时间窗内 `VFR_HUD.climb` 的加权线性拟合；拟合质量不合格时退化为加权均值，并令垂直加速度为零。
- 相对高度必须为正、有限且时间戳不超过 `gps_stale_timeout_sec`，否则不启用动态 R，保留安全 R。

这里的“实际相对高度”是飞控相对 Home 的高度，不是测距仪给出的实时离地高度。当前航线使用相对高度坐标系，所以两者采用同一高度基准；若场地起伏明显，仍需单独接入地形或测距信息。

## 解算过程

从固定安全偏移 `release_offset_m` 开始迭代。每轮先由当前 R 猜测计算 B 到 R 的时间：

```text
t_BR = (B_offset - RC_guess) / v_forward
```

再由 B 点实测高度和垂直状态预测 R 点：

```text
h_R  = h_B + vz_B * t_BR + 0.5 * az * t_BR^2
vz_R = vz_B + az * t_BR
```

如果拟合趋势表示飞机正在收敛到平飞，算法只积分到垂直速度归零，不允许把趋势继续外推成反向爬升或下降。随后求解带初始垂直速度的落体时间：

```text
t_fall = (vz_R + sqrt(vz_R^2 + 2 * g * h_R)) / g
RC_new = v_forward * (t_fall + release_delay)
```

当相邻两次 `RC` 差不超过 `dynamic_r_convergence_m` 时收敛；最多执行
`dynamic_r_max_iterations` 次。日志继续记录 `height_b_m`、`predicted_height_r_m`、
`predicted_vz_r_mps`、每轮迭代值和命令高度，便于复盘。

## 不变内容

- `fixed` 模式仍使用固定 46 m 偏移，不进入本算法。
- R 航点的命令高度仍为 `mission_altitude_m`；实测高度只用于弹道投放距离计算。
- A/U/R/投放/D 航线结构、视觉识别、桥接、任务管理、第二次完整上传及 ACK/进度验证逻辑不变。
- 动态输入缺失、过期、计算不收敛、预测高度非法或 RC 越界时，不上传动态 R，继续使用原安全 R。

## 回归检查

新增或调整的单元测试覆盖：

- 平飞时使用实测相对高度计算，而不是命令高度。
- 命令高度 20 m、实测高度 12 m 时，弹道按 12 m 计算，但航点命令高度仍保持 20 m。
- 持续下降会预测更低的 R 点高度并缩短 RC。
- 垂直趋势收敛到平飞时不会被外推成反向运动。
- 垂直拟合质量差时退化为加权均值。
- 相对高度过期、RC 越界等异常仍拒绝动态解算并走原安全回退。
